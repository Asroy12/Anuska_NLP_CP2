

Project Documentation: SMS Spam-Ham Detection and Classification Pipeline


1. Project Overview & Objective

The core objective of this capstone project is to develop an automated, end-to-end machine learning pipeline capable of classifying SMS text messages as either Spam (unsolicited commercial/fraudulent messages) or Ham (legitimate personal or transactional communications).
Text classification is a foundational task in Natural Language Processing (NLP). This project bridges data engineering, text preprocessing, exploratory data analysis (EDA), and machine learning to build an optimization pipeline that shields users from phishing, fraudulent claims, and unwanted advertisements.

2. Exploratory Data Analysis (EDA) & Feature Engineering

Before feeding the text data into machine learning algorithms, statistical analysis and feature engineering were conducted on a sample of 3,000 text messages to uncover the behavioral patterns of text construction:
• Class Imbalance: Initial distribution mapping revealed that the dataset is highly imbalanced, with Ham accounting for the vast majority (≈ 86%) of the data and Spam representing a minority segment (≈ 14%). To handle this correctly, stratified splitting was used during data partitioning to maintain identical class ratios across the training and testing sets.
• Length as a Predictor: Two meta-features were generated: Total Words and Total Chars. Kernel Density Estimate (KDE) visualization showed distinct, non-overlapping behavior between classes. Spam messages exhibit a significantly higher word count and character count tightly clustered around a long-form profile, whereas Ham messages skew heavily toward short, punchy sentence structures.

3. Data Preprocessing & Vectorization Pipeline

Text processing involves isolating semantic value and transforming high-dimensional string arrays into structured numerical tensors:
1. Normalization (Lowercasing): Converts all raw strings to lowercase to prevent the vocabulary space from treating duplicated terms (e.g., "Free" vs "free") as separate entities.
2. Noise Erasure (Punctuation & URL Removal): Strips syntactic markers, special characters, and web links (URLs matching regex pattern https?://\S+|www\.\S+) to isolate raw alphabetic tokens.
3. Stopwords Elimination: Filters out recurrent English grammatical particles (e.g., a, about, above, after) using NLTK's lexicon, focusing the model's attention entirely on high-signal content tokens.
4. Stemming (Porter Stemmer): Applies grammatical mapping to reduce words to their common root or stem (e.g., congratulations → congratul, joking → joke).
5. Term Frequency-Inverse Document Frequency (TF-IDF): The cleaned text is compiled into a matrix using a TfidfVectorizer configured with max_features=2500 and min_df=2. This mathematical transformation weights each token t in document d relative to the entire corpus D:
\(\text{TF-IDF}(t,d,D)=\text{TF}(t,d)\times \log \left(\frac{1+|{}D|{}}{1+\text{DF}(t,D)}\right)+1\)
This ensures that heavily generic words across documents are penalized, while unique, spam-heavy keyword triggers (like free, urgent, win, cash, prize) are mathematically amplified.

4. Model Selection & Justification

Two distinctive model types were selected to construct this classification system: Multinomial Naive Bayes (MultinomialNB) and a Random Forest Classifier.

Model 1: Multinomial Naive Bayes (MultinomialNB)

• Why it was chosen: Naive Bayes is a probabilistic framework based on the application of Bayes' Theorem under the strong assumption of independence between features (words). For text classification using TF-IDF word vectors, the multinomial variant is computationally efficient and exceptionally high-performing.
• Performance Evaluation:
	• Accuracy: 97.7%
	• Precision: 1.000 (100% precision rate)
	• Recall: 82.9%
	• F1-Score: 0.907
• Strategic Advantage: The Multinomial Naive Bayes achieved a Precision Score of 1.000. In a production-grade spam filter, Precision is the most critical metric. A precision of 1.000 means that the model committed zero False Positives—not a single legitimate, critical personal message (Ham) was mistakenly flagged as Spam and hidden from the user.

Model 2: Random Forest Classifier

• Why it was chosen: Random Forest is an ensemble meta-estimator that fits a multitude of structural decision trees on various subsamples of the dataset, using averaging to control over-fitting and stabilize variance. It handles non-linear interactions between TF-IDF features and token structures exceptionally well.
• Performance Evaluation:
	• Accuracy: 97.7%
	• Precision: 0.986%
	• Recall: 84.1%
	• F1-Score: 0.908
• Strategic Advantage: While the Random Forest model traded a tiny fraction of precision (98.6% vs 100%), it yielded a higher Recall score (84.1% vs 82.9%). This means the Random Forest is slightly more aggressive at catching elusive spam messages that the Naive Bayes model let slip through, providing an optimal alternative depending on how stringently the filter needs to be tuned.

5. Inference and Operational Deployment

Both models show excellent Receiver Operating Characteristic (ROC) behavior, with an Area Under the Curve (AUC) approaching near-perfection (0.99+).
To demonstrate deployment readiness, an interactive inference function (predict_message) was created. When evaluating real-world vector anomalies like: "Congratulations! You've won a free iPhone. Click here to claim.", the vectorized processing instantly maps the tokens to their stems, evaluates the probability vector distribution, and flags it accurately as a Spam Message with an 86% probability score, confirming the pipeline's real-world reliability.
